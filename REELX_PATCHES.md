# Reelx engine patches

Patch set on top of Flutter `3.47.9` (engine revision `89c39edfdfae2949f6806e4a315c0c08522238b7`, content hash `9e025265bef30b838c0c1b68cad19decf97048f2`) for Reelx's export path on every platform the editor ships. One commit per patch on branch `engine-perf/3.47.9`, in the order below; patches not yet built and tested on every platform wait on `engine-perf/3.47.9-wip`.

Moved from 3.47.7 on 2026-11-10 to match the Flutter version the editor builds with (a swapped engine must match the app's Flutter exactly); the rebase had no conflicts. `engine-perf/3.47.7` and `-wip` stay as they were. Status lines dated before 2026-11-10 were measured on 3.47.7. A patch that is useful beyond Reelx may be offered upstream.

To build the engine and use it on a machine (CLI renders, `flutter test`, app builds), see [reelx/ENGINE_SETUP.md](reelx/ENGINE_SETUP.md).

Every patch is behind a feature flag that `ReelxSetFeature` can turn off at run time and that `ReelxEngineInfo` reports.

## Upgrading to a new Flutter release

```sh
git fetch https://github.com/flutter/flutter.git --tags
git switch -c engine-perf/<new> engine-perf/3.47.9
git rebase --onto <new> 3.47.9
```

Then follow each patch's **Verify** steps, rebuild (`reelx/tools/build_engine.sh`), package (`reelx/tools/package_artifacts.py`; the `Engine release` workflow does all platforms), and re-run the export benchmark before releasing `engine-<new>-ext.<n>`.

## Entry format

Each patch has: **Id**, **Title**, **Why** (what an export pays for without it), **Files**, **Tests**, **Verify** (after a rebase), **Feature** (the `ReelxEngineInfo.features` key).

## P2 — Pooled targets and one-copy readback off the IO thread

- **Status**: on `engine-perf/3.47.7-wip`; built and tested on Linux (host_debug_unopt, 2026-11-09): the P2a tests pass on OpenGLES, `ImageEncodingReelxTest.*` pass, and a Reelx export with `oneCopyReadback` on is byte-identical to the stock engine's. Pooled readback buffers (P2b's buffer half) are not written: the copy they would save is gone with the zero-copy hand-over; the stats keys stay for them.
- **Why**: every snapshot allocates a new resolve texture, every readback a new buffer, and the readback copies the frame again on the IO thread.
- **Files**: P2a (`targetPool`) `impeller/display_list/dl_dispatcher.{h,cc}` (`DisplayListToTexture(..., pooled_target, pool_hit)`: one-level targets from a pool of three on the `ContentContext`, reused once nothing else holds them, lazy-mip state cleared), `impeller/entity/contents/content_context.h` (`GetSnapshotTargetPool`), `shell/common/snapshot_controller_impeller.cc` (pooled while `lazyMips` and `targetPool` are on; counts `targetPoolHits`/`Misses`). P2b/P2c (`oneCopyReadback`) `lib/ui/painting/image_encoding.cc`: `rawUnmodified` hands Dart the downloaded buffer itself (`SkData::MakeWithProc` holding the raster image), other raw formats swizzle in one pass straight into the returned data (`SkPixmap::readPixels`), and the copy runs on the concurrent worker runner instead of the IO thread.
- **Fix (2026-11-10)**: a reused target keeps the framebuffer its backend cached for it (Vulkan `TextureSourceVK` frame data, GLES `TextureGLES` cached FBO), and that cache also holds the previous render target's MSAA and stencil textures, which are gone. On Vulkan (SwiftShader, `flutter test --enable-impeller`) the second snapshot aborted on a freed image view; on GLES the old stencil stayed attached. `TargetFromPool` now calls `Texture::ForgetRenderTargetCaches()` (a new virtual, no-op by default; `TextureVK` clears its frame data, `TextureGLES` drops its FBO) on reuse, so a reused target costs one new framebuffer, as a stock snapshot does. Metal caches nothing on the texture. Files: `impeller/core/texture.h`, `impeller/renderer/backend/vulkan/texture{,_source}_vk.{h,cc}`, `impeller/renderer/backend/gles/texture_gles.{h,cc}`.
- **Tests**: `AiksTest.ReelxPooledTargetIsReusedOnceReleased`, `ReelxMipmappedTargetsAreNotPooled`, `ReelxReusedTargetDrawsLikeAFreshOne`, `RenderPassVK.ForgottenRenderTargetCachesMakeANewFramebuffer` (mock Vulkan), `TextureGLESTest.ForgetRenderTargetCachesDropsTheCachedFBO` (`impeller_unittests`); `ImageEncodingReelxTest.OneCopyKeepsTheBytes`, `OneCopyUnmodifiedIsTheImagesOwnMemory` (`ui_unittests`).
- **Verify**: the tests above; Reelx's gated determinism suite byte-identical with `oneCopyReadback` on and off; the export log's pool hit rate near 100 % after the first frames.
- **Feature**: `targetPool`, `oneCopyReadback`

## P4 — Native frame hand-off to a file descriptor

- **Status**: on `engine-perf/3.47.7-wip`; built and tested on Linux (host_debug_unopt, 2026-11-09): `ReelxFfiTest.*` pass, `flutter_tester` exports the three functions, and a Reelx export through `ReelxImageReadbackToFd` (Skia path) is byte-identical to the stock engine's; the writer logic was also checked off-tree under ThreadSanitizer.

Exported by the existing `Reelx*` symbol patterns.
- **Tests**: `ReelxFfiTest.Handoff*` in `ui_unittests` (refusals before any image); the readback path is Reelx's `frame_handoff_export_test.dart` against the real engine.

## P7 — Fragment shaders from bytes

- **Status**: on `engine-perf/3.47.7-wip`; built and tested on Linux (host_debug_unopt, 2026-11-10).
- **Why**: a shader effect or transition otherwise has to ship as an asset in the app bundle; with bytes, effects can come from code or downloaded packs.
- **What**: `ReelxRegisterShaderBytes(key, bytes)` (FFI `Handle` arguments: a `String` and a `Uint8List`, so no `malloc` on the Dart side) keeps a copy of an impellerc bundle (`impellerc --iplr`, the file the flutter tool builds for a `.frag` in pubspec's `shaders`) under `key` for the whole process; `FragmentProgram.fromAsset(key)` finds it before the asset manager. `dart:ui` is unchanged, so the stock API loads it, and a stock engine simply lacks the symbol. Returns `0`, `-1` bad argument, `-3` not a shader bundle (checked with `RuntimeStage::DecodeRuntimeStages`); `ReelxUnregisterShaderBytes(key)` returns `0` or `-4`. `dart:ui` keeps the program it loaded for a key (`_shaderRegistry`) and encodes keys like asset keys (`Uri.encodeFull`), so use plain keys and a new key for changed bytes (a content hash). The bytes must hold a stage for the backend the app runs on (`--runtime-stage-metal` for macOS/iOS Impeller, `--sksl` for Skia, GLES/Vulkan for Linux/Android).
- **Files**: `lib/ui/reelx/reelx_shader_bytes.{h,cc}` (store + C API), `lib/ui/painting/fragment_program.cc` (`initFromAsset` asks the store first), `lib/ui/BUILD.gn`.
- **Tests**: `lib/ui/reelx/reelx_shader_bytes_unittests.cc` (`ReelxShaderBytesTest.*` in `ui_unittests`: round trip, decodes like the asset, junk and cut bundles refused, replace, unregister keeps live mappings). End to end (a Flutter test, outside the tree): register an impellerc bundle over FFI, `FragmentProgram.fromAsset`, draw, check pixels; passes with Skia and with `--enable-impeller` (Vulkan/SwiftShader), skipped on the stock engine.
- **Verify**: `ui_unittests --gtest_filter='ReelxShaderBytes*'`; `nm` shows `ReelxRegisterShaderBytes` / `ReelxUnregisterShaderBytes` in `flutter_tester` and `FlutterMacOS.framework`.
- **Feature**: none (the symbol's presence is the capability)

## P13 — Snapshots draw from host buffers of their own

(P8 to P12 are kept for patches that are not written yet.)

- **Status**: on `engine-perf/3.47.9-wip`; built and tested on Linux (host_debug_unopt, 2026-11-10): OpenGL ES unit tests pass, and Vulkan (SwiftShader) is covered by the measurement below. Metal runs in the macOS CI only.
- **Why**: Impeller draws every frame's vertices and uniforms from "transient" host buffers that are reset at the end of an on-screen frame. A snapshot (`Picture.toImage`, `Scene.toImage`) draws from the same buffers and never resets them, and an export has no on-screen frames, so the buffers only grow: 3000 snapshots of 400 rectangles add 646 MB to the process (Vulkan, `flutter_tester --enable-impeller`), 65 MB with this patch (44 MB of it in the first 500 frames), 26 MB on Skia. Frame time is unchanged (about 16.5 ms in that debug build).
- **What**: while a snapshot is drawn, `ContentContext` hands out a second pair of host buffers (made on the first snapshot) and gives the frames' pair back afterwards, so on-screen frames are untouched. After the snapshot's command buffers are submitted the snapshot buffers are reset, but only when the GPU has finished with the arena entry a reset hands out next: each snapshot marks the entry it wrote to (`HostBuffer::MarkInFlight`) and an empty command buffer submitted after the snapshot's work clears the mark from its completion callback, on whatever thread the backend calls it; `HostBuffer::ResetIfIdle` refuses while a mark is set. A refused reset just lets the buffers grow for that snapshot, as the stock engine does. Screenshots (`Rasterizer`) and golden tests keep the stock path.
- **Files**: `impeller/core/host_buffer.{h,cc}` (`MarkInFlight`, `ResetIfIdle`, per-entry counters), `impeller/entity/contents/content_context.{h,cc}` (`UseSnapshotTransientsBuffers`), `impeller/display_list/dl_dispatcher.{h,cc}` (`DisplayListToTexture` gets `snapshot_host_buffers` and `host_buffers_reset`; `ResetSnapshotHostBuffers`), `shell/common/snapshot_controller_impeller.cc` (asks for it while the feature is on, counts resets and holds), `lib/ui/reelx/reelx_ffi.{h,cc}` (feature and the `snapshotBufferResets` / `snapshotBufferHolds` counters).
- **Tests**: `HostBufferTest.ReelxResetIfIdleWaitsForWorkInFlight`, `ReelxInFlightIsCountedAndDoneCountsOnce`, `ReelxInFlightDoneMayOutliveTheBuffer` in `impeller/entity/contents/host_buffer_unittests.cc`; `AiksTest.ReelxSnapshotsResetHostBuffersOfTheirOwn` in `impeller/display_list/reelx_snapshot_unittests.cc` (pixels identical to the stock path, every snapshot reset, nothing written to the frames' buffers, the stock path still grows); `ReelxFfiTest.*` for the feature name.
- **Verify**: `impeller_unittests --gtest_filter='*Reelx*:*HostBufferTest*'`; a `flutter test --enable-impeller` loop of `Picture.toImage` + `toByteData` keeps its resident memory flat and `ReelxEngineInfo` shows `snapshotBufferResets` equal to the number of snapshots and `snapshotBufferHolds` at 0 (holds are expected only when the GPU falls behind). After a rebase, check that nothing else in `DisplayListToTexture` reads the frames' host buffers between the swap and the swap back.
- **Feature**: `snapshotBuffers`

## P14 — Snapshot targets keep their MSAA colour and depth/stencil textures

- **Status**: on `engine-perf/3.47.9-wip`; built and tested on Linux (host_debug_unopt, 2026-11-10): OpenGL ES unit tests pass (explicit MSAA), Vulkan has a mock-device test and the measurement below (SwiftShader). Metal runs in the macOS CI only. Not covered: OpenGL ES drivers that resolve MSAA implicitly (most Android GLES devices), where the patch does nothing yet.
- **Why**: P2's pool reuses the texture a snapshot is resolved into, but every snapshot still allocated a multisampled colour texture and a depth/stencil texture of the frame's size and threw them away, and the pooled texture had to forget the framebuffer the backend cached for it, because that framebuffer pointed at the textures just thrown away. A 1280x720 snapshot loop on Vulkan (`flutter_tester --enable-impeller`, SwiftShader, debug build) goes from about 30.5 to 21.5 ms per frame with one snapshot size, and from about 35.5 to 29.5 ms with two sizes per frame; the bytes read back are identical. These are CPU-rasterizer numbers: they show the work removed, not what a GPU driver will save.
- **What**: the pool on `ContentContext` now also keeps up to two sets of {MSAA colour, depth/stencil}, one per snapshot size and format (an export draws the frame at one size and, when it packs the frame for the encoder, at a second). `DisplayListToTexture` builds the snapshot's render target from the set for its size and attaches the depth/stencil texture itself, with the configuration `Canvas` would use, so `Canvas` leaves it alone. Both attachments are cleared on load by every pass, so nothing of the previous snapshot can show. Each set has an id that changes whenever its textures do; a pooled result texture remembers the id it was last drawn with and calls `ForgetRenderTargetCaches` only when that id differs, so the Vulkan framebuffer and render pass (and the OpenGL ES framebuffer objects) are made once per size instead of once per snapshot. A third size replaces the least recently used set. Memory: the sets stay allocated between snapshots (about 45 MB for one 1280x720 set on desktop Vulkan; memoryless attachments on Apple silicon cost nothing). After 300 on-screen frames without a snapshot the sets and the pooled result textures nobody holds are let go (this also trims P2's pool, which used to keep its textures for the life of the context); a process that draws no on-screen frames keeps them until the context goes. Where the driver resolves MSAA implicitly the feature is ignored and the stock attachments are used.
- **Files**: `impeller/entity/contents/content_context.{h,cc}` (`SnapshotTarget`, `SnapshotAttachments`, `SnapshotTargetPool`; the idle trim in `ResetTransientsBuffers`), `impeller/display_list/dl_dispatcher.{h,cc}` (`DisplayListToTexture` gets `pooled_attachments` and `attachments_hit`; `AttachmentsFromPool`, `AttachFromPool`; the forget decision moved out of `TargetFromPool`), `impeller/display_list/canvas.{h,cc}` (`Canvas::GetRootStencilConfig`), `shell/common/snapshot_controller_impeller.cc` (asks for it while `targetPool` and the feature are on, counts hits and misses), `lib/ui/reelx/reelx_ffi.{h,cc}` (feature and the `targetAttachmentHits` / `targetAttachmentMisses` counters).
- **Tests**: `AiksTest.ReelxSnapshotsShareAttachments` (pixels identical to the stock path with clips, one set shared by a held and a reused target, sets dropped when a snapshot does not ask for them), `ReelxAttachmentsFollowTheSnapshotSize` (two sizes alternate without misses, a third replaces the least recently used, a replaced set gets a new id), `ReelxIdleSnapshotPoolLetsGo` in `impeller/display_list/reelx_snapshot_unittests.cc`; `RenderPassVK.KeptAttachmentsKeepTheFramebuffer` in `impeller/renderer/backend/vulkan/render_pass_vk_unittests.cc` (a second render target made of the same three textures creates no framebuffer and no render pass); `ReelxFfiTest.*` for the feature name.
- **Verify**: `impeller_unittests --gtest_filter='*Reelx*:RenderPassVK.*'`; a `flutter test --enable-impeller` loop of `Picture.toImageSync` + `toByteData` with clipped content returns the same bytes with the feature on and off, and `ReelxEngineInfo` shows one `targetAttachmentMisses` per snapshot size (plus one per size change beyond two) and hits for the rest. After a rebase, check that `Canvas::SetupRenderPass` still skips a render target that already has a depth attachment, that `InlinePassContext` still clears depth/stencil and the MSAA colour on load, and that `GetRootStencilConfig` still returns what `SetupRenderPass` passes to `SetupDepthStencilAttachments`.
- **Feature**: `targetAttachments`

## P15 — Decoded images fill their mipmaps on first use

- **Status**: on `engine-perf/3.47.9-wip`; built and tested on Linux (host_debug_unopt, 2026-11-10): OpenGL ES unit tests pass, Vulkan is exercised by the measurement below (SwiftShader). Metal runs in the macOS CI only.
- **Why**: every image that `ImageDecoderImpeller` uploads (`instantiateImageCodec`, `ImageDescriptor`) gets its full mipmap chain generated before the image is handed to Dart, even when nothing ever samples a level above 0. A decoded video frame drawn at its own size, which is what an export does once per frame, pays for the whole chain and never reads it. A 1280x720 per-frame decode + draw + readback loop on Vulkan (`flutter_tester --enable-impeller`, SwiftShader, debug build) goes from about 32–40 to 22–25 ms per frame (two runs each, alternated). These are CPU-rasterizer numbers: they show the work removed, not what a GPU will save.
- **What**: with the feature on, the upload keeps the stock texture (every mip level allocated) but skips `GenerateMipmap` and marks the texture as having deferred mipmaps (`Texture::SetDeferredMipmaps`). When the upload resizes on the GPU, the intermediate texture has one level (the resize reads only level 0) and the resized texture is deferred the same way. Every way a draw reaches an image's texture goes through `DlImageImpeller::GetCachedTexture`, which now fills deferred mipmaps first (own command buffer, submitted before the draw's), so image shaders, runtime-effect samplers, image filters, vertices, nine-patch and atlas draws see what a stock upload gives them; so does flutter_gpu's `Texture` from a `ui.Image`. Only `drawImage` / `drawImageRect` look at the texture as uploaded: when the draw can read level 0 alone (no image filter, colour filter, mask blur, inverted colours or advanced blend on its paint, and either a sampler without mipmaps or a scale-and-translate transform under which no texel gets less than a pixel), its sampler is switched to base level only and the mipmaps stay unfilled; otherwise they are filled then. The same rule spares P1's lazy snapshots their mipmapped copy when they are drawn at their size. Trade-off for apps: a minified image's mipmaps are now made on the raster thread at its first draw instead of on the IO thread at decode; apps that mind switch the feature off.
- **Pixels**: wherever mipmaps are filled, the bytes are identical to the stock path (minified draws, blur, rotation, image shader, resize uploads). Where the draw reads level 0 alone, the result can differ from the stock mipmap sampler by one step in a few pixels: on SwiftShader 1165 of 3.7 million bytes of a 1280x720 frame differ by 1, and both paths are within 2 of the source pixels there, because the driver filters differently for a mipmap sampler at level 0 than for a base-level sampler.
- **Files**: `impeller/core/texture.{h,cc}` (`SetDeferredMipmaps`, `HasDeferredMipmaps`), `impeller/display_list/lazy_mipmaps.{h,cc}` (`GenerateDeferredMipmaps`, `ImageRectNeverMinifies`, the generated counter), `impeller/display_list/dl_image_impeller.{h,cc}` (`GetCachedTexture` fills, `GetCachedTextureAsUploaded` doesn't), `impeller/display_list/dl_dispatcher.{h,cc}` (`drawImageRect`'s level-0 rule, `SamplesImageOnce`), `lib/ui/painting/image_decoder_impeller.cc` (the deferred upload), `lib/gpu/texture.cc`, `lib/ui/reelx/reelx_ffi.{h,cc}` (feature and the `imageMipsDeferred` / `imageMipsGenerated` counters).
